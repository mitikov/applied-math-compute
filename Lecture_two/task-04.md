Раніше ви змінювали окрему комірку. Тепер **одна формула діятиме на всі пікселі**. Для одноканальної матриці правило має вигляд `B[row, col] = f(G[row, col])`. У цих операціях результат пікселя не залежить від сусідніх пікселів.

```python
import numpy as np
import matplotlib.pyplot as plt

G = np.array([
    [ 0, 40,  80, 120, 160, 200],
    [20, 60, 100, 128, 180, 220],
    [30, 70, 110, 150, 190, 230],
    [50, 90, 130, 170, 210, 250]
], dtype=np.uint8)

RGB = np.array([
    [[ 40,  80, 200], [220, 160,  20], [128, 128, 128], [255, 255, 255]],
    [[255,   0,   0], [  0, 255,   0], [  0,   0, 255], [  0,   0,   0]]
], dtype=np.uint8)

def show_images(items):
    fig, axes = plt.subplots(1, len(items), figsize=(4 * len(items), 3))
    for ax, (data, title) in zip(np.atleast_1d(axes), items):
        if data.ndim == 2:
            ax.imshow(data, cmap="gray", vmin=0, vmax=255,
                      interpolation="nearest", origin="upper")
        else:
            ax.imshow(data, interpolation="nearest", origin="upper")
        ax.set_xticks(range(data.shape[1]))
        ax.set_yticks(range(data.shape[0]))
        ax.set_title(title)
        ax.set_xlabel("Стовпець")
        ax.set_ylabel("Рядок")
    plt.tight_layout()
    plt.show()

# Спочатку обмежуємо діапазон, потім округлюємо й повертаємо uint8.
def to_uint8(values):
    return np.rint(np.clip(values, 0, 255)).astype(np.uint8)

show_images([(G, "Початкова матриця"), (RGB, "RGB-мозаїка")])
```

Матриця `G` подібна до матриці із завдання 2, але елемент `[1, 3]` тут дорівнює `128`: він потрібен для перевірки точного потрапляння на поріг.

### Зміна яскравості

Дослідіть правило `p_new = clip(p + k, 0, 255)`. Функція `clip` залишає значення в діапазоні `0–255`, замінює менші на `0`, більші на `255`.

```python
# Змінюйте k: -60, 0, 40, 100.

raw = G.astype(np.int16) + k
bright = to_uint8(raw)

print("Форма й тип результату:", bright.shape, bright.dtype)
print("Значень нижче 0 до обмеження:", np.count_nonzero(raw < 0))
```

### Чому додавання в uint8 може зіпсувати зображення

`uint8` може зберігати тільки цілі числа від `0` до `255`. Зараз порівняйте додавання в цьому типі з обчисленням у ширшому типі й подальшим обмеженням діапазону.

1. Перед запуском спрогнозуйте результати обох способів для початкових значень `210` і `250`.
2. Запустіть код. Поясніть числа в останньому рядку `unsafe` і `safe`.
3. Перевірте спробу відновлення: після правильного додавання `40` та обмеження до `255` відніміть `40`. Запишіть кількість пікселів, які не відновилися, і поясніть причину.

```python
# Обидва операнди мають тип uint8: результат може переповнитися.
unsafe = G + np.uint8(40)
safe = to_uint8(G.astype(np.int16) + 40)

print("Останній рядок оригіналу:", G[-1])
print("Додавання в uint8:", unsafe[-1])
print("З обмеженням діапазону:", safe[-1])

# Спроба скасувати додавання після збереження результату в uint8.
restored_brightness = to_uint8(safe.astype(np.int16) - 40)
lost_pixels = np.count_nonzero(restored_brightness != G)
print("Пікселів, які не відновилися:", lost_pixels)

show_images([
    (G, "Початкове"),
    (unsafe, "Додавання в uint8"),
    (safe, "Додавання з clip")
])
```

У наведеному додаванні операндів типу `uint8` переповнені значення переходять через межу за модулем `256`. Це інша дія, ніж обмеження через `clip`. Перетворення на ширший тип **після** такого додавання вже не виправить отриманих чисел.

Безпечний порядок у цьому завданні: **розширити тип → виконати арифметику → обмежити діапазон → округлити → повернути uint8**. Ширший тип також має свої межі; `int16` достатній для заданих тут значень `k`.

### Окремі коефіцієнти для RGB-каналів

Застосуйте правило `(R_new, G_new, B_new) = (k_R R, k_G G, k_B B)` із подальшим обмеженням діапазону й округленням.

3. Заповніть таблицю та порівняйте результат для сірого пікселя `RGB[0, 2]`. Чи залишається він сірим?

```python
# Змінюйте gains: (1,1,1), (1.5,1,1), (1,0.5,1), (1,1,0).
gains = np.array([1.5, 1.0, 1.0])

if gains.shape != (3,) or not np.all(np.isfinite(gains)) or np.any(gains < 0):
    raise ValueError("Потрібні три скінченні невід'ємні коефіцієнти")

raw_rgb = RGB.astype(np.float64) * gains
scaled_rgb = to_uint8(raw_rgb)

print("Форма RGB:", RGB.shape)
print("Форма коефіцієнтів:", gains.shape)
print("Форма результату:", scaled_rgb.shape)
print("Компонент понад 255 до обмеження:",
      np.count_nonzero(raw_rgb > 255))
for row, col in [(0, 0), (0, 1), (0, 2)]:
    print(
        (row, col), "RGB до =", RGB[row, col],
        "до обмеження =", raw_rgb[row, col],
        "RGB після =", scaled_rgb[row, col]
    )

show_images([(RGB, "Початкове RGB"), (scaled_rgb, f"Коефіцієнти: {gains}")])
```

| Коефіцієнти R, G, B | Прогноз RGB[0,0] | Фактичний RGB[0,0] | RGB сірого пікселя після зміни | Компонент понад 255 до clip | Що спостерігали |
| --- | --- | --- | --- | ---: | --- |
| `(1,1,1)` | | | | | |
| `(1.5,1,1)` | | | | | |
| `(1,0.5,1)` | | | | | |
| `(1,1,0)` | | | | | |

Вектор `gains` має форму `(3,)`. NumPy застосовує його до останньої осі RGB-масиву — каналів кожного пікселя. Це **broadcasting**: не потрібно вручну створювати окрему копію коефіцієнтів для кожного рядка й стовпця. Оператор `*` виконує поелементне множення з broadcasting; це не матричний добуток `@`.

Цей дослід змінює баланс каналів за заданими коефіцієнтами. Він ще не визначає автоматично, які коефіцієнти потрібні для виправлення освітлення.
