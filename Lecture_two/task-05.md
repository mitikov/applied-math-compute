# Практичні завдання до лекції 2

## Завдання 5. Гамма-корекція в онлайн-лабораторії

**Мета:** дослідити нелінійне попіксельне перетворення зображення та перевірити пояснення сервісу за формулою й результатом.

**Орієнтовний час:** 15 хвилин.

**Інструмент:** [Image Play Lab](https://imageplaylab.com/lab). Для цієї вправи достатньо браузера; писати код не потрібно.

У [завданні 4](task-04.md) ви додавали однакове число до значень пікселів. Тут дослідіть інше правило:

```text
p_new = 255 · (p / 255)^(1 / γ), де γ > 0
```

Тут `p` — значення однієї компоненти пікселя в діапазоні `0–255`. Для RGB-зображення правило застосовується окремо до компонент R, G і B. Результат зберігається як ціле число. У різних інструментах гамму можуть визначати через показник `γ` або `1/γ`, тому завжди звіряйте формулу.

### Підготовка

1. Відкрийте сайт і виберіть вбудоване зображення **Landscape**. Це тестовий малюнок із небом, горами, сонцем і зеленою ділянкою.
2. У розділі **Image Basics** виберіть **Gamma Correction**.
3. Увімкніть **Split**, щоб бачити оригінал і результат поруч. У блоці **Histogram** залиште **Gray**.
4. Знайдіть повзунок **Gamma (γ)**. Для точнішого встановлення значення можна сфокусувати повзунок і скористатися клавішами зі стрілками.

### Дослід

1. **До зміни повзунка** запишіть прогноз для `γ=0.5`, `1.0`, `2.0`: які ділянки зміняться і в який бік?
2. Послідовно встановіть ці три значення. Для кожного порівняйте небо, гори й зелену ділянку з оригіналом. Розгляньте гістограму результату: де зосереджені значення — ближче до `0` чи до `255`?
3. Для початкового значення `p=128` обчисліть результат за формулою для кожної гамми. Можна використати калькулятор або Python; запишіть результат до округлення з одним знаком після коми.
4. Заповніть таблицю. Зміни не потрібно застосовувати одна за одною як ланцюжок: порівнюйте кожне налаштування з тим самим оригіналом.

| ---: | --- | ---: | --- | --- |
| 0.5 | | | | |
| 1.0 | | | | |

Гістограма показує розподіл значень: по горизонталі — рівень інтенсивності, по вертикалі — кількість пікселів із відповідним рівнем. Для кольорового зображення режим **Gray** дає узагальнений розподіл яскравості. Він не показує, де саме розташовані пікселі, і не замінює три окремі RGB-гістограми. У цій вправі достатньо якісного порівняння; точні кількості з графіка зчитувати не потрібно.

### Перевірте пояснення сервісу

Розгорніть **Insights** кнопкою **expand** і відкрийте вкладку **Math**. Порівняйте формулу гамма-корекції з підказкою під повзунком і своїми спостереженнями.

**Запишіть, чи узгоджуються ці три джерела.** Якщо знайшли суперечність, вкажіть конкретне твердження та наведіть доказ: розрахунок для `p=128` і спостереження за зображенням.

Можна використати ШІ для перекладу англомовного пояснення, але висновок обґрунтуйте власним дослідом.

### Питання до результатів

1. Що відбувається при `γ=1`? Чому? Перевірте також за формулою, чи змінюються значення `p=0` і `p=255` при двох інших гаммах.
2. Чим гамма-корекція відрізняється від додавання сталої яскравості із завдання 4? Чи однаковою буде зміна для `p=64` і `p=192` при `γ=2`? Підтвердьте розрахунком.
3. Чи можна за однією гістограмою визначити, де на зображенні розташовані гори? Поясніть відповідь.

**Межі моделі:** це дослід степеневого перетворення числових компонент зображення. Візуально світліший результат сам по собі не доводить правильного відновлення освітлення сцени або фізично коректного кольору. Операція не додає нових деталей до вихідних даних; округлення до цілих значень може об'єднати різні початкові значення.
